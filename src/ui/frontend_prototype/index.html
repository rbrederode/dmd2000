Changes apply to this run after processing. Interactive plot adjustments start from the processed aggregates. Use Save Pipeline Configuration to keep these settings in the selected Config Profile.

            

              

              

                
How the pipeline works

                
A context identifies the stage at which a pipeline step operates on a spectrum. The normal flow is spr → cal → mpr. At each stage, the processor executes only enabled steps assigned to that context, in their configured order. The first step receives that stage's input spectrum; its output spectrum and channel-quality flags become the input to the next step, and so on until the last matching step returns the stage's result. Disabled steps and steps assigned to other contexts are skipped. For example, in cal, LOAD normalization can feed bandpass selection, then RFI flagging, then baseline subtraction.

                
1. spr — Summed Power Spectrum
The spr context processes summed power per channel per second. During acquisition, FFT power samples are summed within each frequency channel over one second, producing one summed-power spectrum for that second. Enabled spr steps run on each of these spectra in order, for example to remove a DC spike. The resulting per-channel, per-second SPR data is recorded in spectrum files in the scan store for processing and reprocessing. Keep spr processing minimal because these saved spectra are the starting point for future reprocessing.
2. cal — Calibrated Spectrum
The cal context applies calibration and correction steps to the summed power per channel per second. For each second, the processor takes a copy of its SPR spectrum and passes it through the enabled cal steps in order, with each step receiving the previous step's result. The output remains one calibrated value per channel per second; this stage does not average the seconds together. It runs during acquisition and again when saved spectra are processed, preserving the saved SPR data as the starting point for reprocessing. A typical sequence is LOAD normalization, bandpass selection, RFI flagging, then optional baseline subtraction. Corrections change spectral values; flagging steps mark channels to exclude from subsequent calculations without replacing their measured values.
3. mpr — Mean Power Spectrum
The mpr context operates on reduced data: the mean of the calibrated per-second samples in each channel. The processor first averages the usable per-second values across the loaded seconds, separately for each channel, reducing the series of calibrated spectra to one mean spectrum with one value per channel. For example, ten usable one-second samples in a channel are summed and divided by ten. Flagged samples are excluded from that channel's mean and channel-quality flags are carried forward. Enabled mpr steps then process this mean spectrum in order, passing their results from step to step. QA normally runs here to measure noise, SNR and other quality statistics without changing the spectrum. As samples arrive, MPR and its statistics are updated.
When changes take effect and how to return to SPR
During observation processing, OPT reads saved SPR files and forms target/frequency aggregates. Saved SPR data already starts after the original spr stage; this input path does not replay spr steps. It runs cal processing and rebuilds MPR instead. Changing a spr-only step here therefore does not redo that correction on saved SPR files.
Selecting a context does not run a step immediately. The processor invokes that context when it reaches the corresponding stage. The table groups spr, cal and mpr to show this flow; the configuration order is retained within each group.
Checking an unconfigured step adds it to this run. Unchecking a step skips it while retaining its settings. Process or Reprocess observation applies pipeline changes to the aggregates. Use Save Pipeline Configuration to keep changes in the selected Config Profile.
You can always return to the saved SPR starting point by reprocessing the spectrum files. Each processing run reads those files afresh and rebuilds the calibrated and mean spectra; it does not apply the new pipeline on top of the previous run's corrected results. To recover the saved SPR spectrum without calibration or other corrections, uncheck the cal and mpr steps that change spectral values, then choose Process or Reprocess observation. The mean is then formed from the saved SPR samples. Reprocessing does not overwrite the source spectrum files, so you can change the settings and try again. This restores the saved SPR, including any spr-stage corrections already recorded during acquisition; undoing those requires the original raw IQ samples.
Interactive plot adjustments start from the processed aggregates and do not rerun this pipeline. Update plots changes derived views; selecting no interactive baseline subtraction restores the processed aggregate, including any pipeline correction already applied.
Choose a question mark beside an individual step for its purpose, parameters and usage notes. The question mark beside Pipeline Steps returns to this guide.

              

            

            
Advanced JSON editor
Use the fields beside each step to adjust its parameters. Steps run in listed order within each context. Use JSON for adding, removing or reordering steps and digitiser-specific lists. Keep LOAD calibration references intact. Baseline ranges_pct selects percentiles of usable channels.
Use default for all digitisers, or add a digitiser-specific list. An empty list disables processing for that entry.
